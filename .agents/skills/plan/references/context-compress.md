# 上下文压缩（何时 / 怎么压）

目标：聊天窗口只保留**当前任务所需**；可恢复状态落在 `plan/`，不依赖长对话。

## 推荐压缩时机（按优先级）

| 优先级 | 时机 | 为什么 |
|--------|------|--------|
| P0 | **一块可交付改动完成**（feature 打通、bug 修完、技能改完） | 结果已进代码 / `CURRENT`，中间探索可丢 |
| P0 | **用户换话题 / 新开一大块任务** | 旧任务细节会污染下一步推理 |
| P0 | **用户说继续 / 换电脑 / 新开对话前** | 用 `CURRENT.md` 接续，禁止复述整段旧聊天 |
| P1 | **准备加载多个重技能或大段 references** | 先落盘进度，再按路由按需读，避免窗口叠满 |
| P1 | **探索跑偏或试错结束**（错误方案已排除） | 只把「结论 / 不要做」写入 plan，删掉试错过程 |
| P2 | **同一对话已多轮工具输出、读过很多大文件** | 主动 checkpoint 更新 `CURRENT`，后续只引用路径 |
| P2 | **用户明确要求压缩 / 记进度 / 收工** | 立即执行，不必等大里程碑 |

**不要**在「改到一半、下一步必须依赖刚读的未落盘细节」时硬压——先用 3～5 行写入 `CURRENT`「进行中」再压。

## 压缩做什么（动作清单）

1. **更新** `plan/CURRENT.md`（权威）：目标、已完成、进行中（卡点 + 路径）、下一步、关键决定、不要做。
2. **可选**：长设计 / 对比方案 → `plan/<topic>.md`；`CURRENT` 只留一句指针。
3. **自检体积**：`CURRENT` 应能一眼扫完（约 **≤80 行**）；超出则把过期「已完成」收成一行摘要，或移到专题文件。
4. **回复用户**：极短状态确认（1～3 句），**禁止**把刚写入的 `CURRENT` 全文贴回聊天。
5. **若任务已收口且下一任务无关**：建议用户**新开对话**续作（读 `CURRENT` 即可）。

## 压什么 / 留什么

| 留下（进 plan 或实码） | 丢掉（不再复述） |
|------------------------|------------------|
| 目标、下一步、关键路径 | 大段构建日志、重复 `git status` |
| 已拍板的设计决定 | 被否决的方案全文 |
| 已知坑 / 约定例外 | 已合并进文件的草稿讨论 |
| 「不要做」清单 | 读过的 skill / reference 原文 |
| 实际构建 / 测试命令 | 猜出来的、未验证的命令 |

## 与 skills 渐进式披露配合

- 压缩**不是**少读 skills，而是：**先 checkpoint，再按总入口路由只读需要的子技能 / reference**。
- assets / 长 reference：**执行或按点名读**，不要为了「压缩」而整文件贴进聊天。
