# Git 安全与不要做

## 原则

- **本地 commit：本仓库默认自动**（完成一小段可验证改动即提交，无需用户再说「提交」）。
- **远程写：默认禁止**；须用户当轮**明确**授权。
- **破坏性远程操作默认拒绝**（删仓、force 主分支等），除非极明确措辞并二次确认。

## 绝对禁止（无明确授权）

1. 任何推送：`git push`、`push -u`、`push --all`、`push --tags`、`push --delete`。
2. 删除远程仓库：`gh repo delete`、托管平台 Delete repository、清空 remote、转让 Owner。
3. 删除 / 覆盖远程分支与历史：对 `main` / `master` 的 `push --force` / `force-with-lease`；未授权的 `push --delete`。
4. 改 `git config`（含 credential、破坏性改 remote）。
5. 擅自 `--no-verify`。
6. 提交 `.env`、真实密钥、内网密码明文。
7. 未确认的 `reset --hard` / `clean -fd`。
8. `rebase -i`、`add -i` 等交互式命令。

## 高危远程：删除仓库

| 步骤 | 要求 |
|------|------|
| 触发 | 仓库全名（如 `owner/repo`）+「确认删除远程」 |
| 再确认 | Agent 复述对象与不可恢复后果，等再次肯定 |
| 否则 | **只解释风险，不执行** |

模糊说法（「清一下远程」「删了吧」）→ **拒绝执行**。

## 模糊话术 ≠ 远程授权

不构成 push / 删远程：

- 用户只说做功能、修 bug（此类只会触发**自动本地 commit**）
- 「提交」「检查点」「保存进度」
- 「同步一下」「发布一下」「顺便推了」

须出现：`push` / `推送` / `推到远程` / `推送到 origin` 等。

## 自动本地 commit 边界

- 改到一半、构建 / 校验失败 → 先不 commit。
- 用户说「先别提交」→ 遵守。
- 只 stage 本意图文件；密钥永排除。

## 与通用「未要求不提交」规则

- **本仓库以本技能为准**：完成可验证改动 → **必须**自动本地 commit。
- 该自动授权**仅限本地**；远程写仍须明确指令。

## 本仓库 remote

`origin` 指向内网 Gitea（`http://内网地址:3000/Clash/Clash.git`）。内网地址不等于授权：push 仍须用户当轮明确要求。
