# Clash 1.0.1

本次只有一个主题：**切换订阅不再重启内核**。

## 新增

### 配置热重载

切订阅 / 更新订阅时，不再 `stop → start`，而是复用当前端口与 secret，通过 `PUT /configs` 就地重载配置。

| 场景 | 1.0.0 | 1.0.1 |
|---|---|---|
| 切订阅（本地内核） | 0.69s | **0.055s** |
| 切订阅（TUN 开着） | 0.477s，root 内核换 pid | **0.053s，pid 与 utun 不变** |
| 连续切换 5 次 | 3.28s | **0.272s** |
| App CPU 峰值（切换窗口） | 15.5% | 13.1% |

- TUN 模式下连接不断、路由不重建
- 重载后主动刷新 `/proxies`，策略组与节点列表立即显示新订阅
- 任何一步失败（API 报错 / 内容校验未通过）都会**自动回退**到原来的 stop→start，并记录原因，不会留下半套状态

## 修复

1.0.0 之后没有新增用户可见的 bug 修复；期间修的是 **CI 构建问题**：

- GitHub Actions runner 共享出口 IP，`fetch-kernel.sh` 未认证调用 GitHub API 会被限流（403），导致 `Fetch kernel and geodata` 偶发失败
- 现在 CI 会带上 `GITHUB_TOKEN` 并统一重试，构建稳定性恢复

## 与 1.0.0 相同

以下能力没有变化：

- 菜单栏控制中心面板：系统代理 / TUN / 代理模式 / 订阅一屏完成
- 系统代理与 TUN 互斥，TUN 需要一次管理员授权
- 内核按需下载（SHA256 校验、镜像回退）；`-kernel` 包内置内核
- 多订阅、策略组单选、未生效标注、延迟缓存
- 规则 / 连接 / 日志、网络检测（仅手动触发）
- 单实例、退出还原、崩溃后清理孤儿内核、清理可恢复（废纸篓）

## 已回退的实验（不包含在本版）

- 测速改逐节点滑动窗口：实测总时长 2.0s → 6.4s、TCP 峰值不降反升，已回退
- 面板隐藏时把采样降到 2s：空闲 CPU 0.10% → 0.11%，无可测收益，已回退

## 稳定运行数据

- 连续运行 47.7 小时：无重启、无崩溃
- App 平均 CPU 0.12%，root 内核 0.15%
- footprint 稳定在 49–56MB，无增长趋势
- 经 TUN 的 HTTP 请求 p50 约 0.55s（取决于节点）

## 安装包

| 文件 | 架构 | 内置内核 |
|---|---|---|
| `Clash-1.0.1-arm64.dmg` / `.zip` | Apple Silicon | 否（首次使用下载内核） |
| `Clash-1.0.1-arm64-kernel.dmg` / `.zip` | Apple Silicon | 是（装完即用） |
| `Clash-1.0.1-x86_64.dmg` / `.zip` | Intel | 否 |
| `Clash-1.0.1-x86_64-kernel.dmg` / `.zip` | Intel | 是 |

每个产物附同名 `.sha256`：`shasum -a 256 -c Clash-...sha256`

## 系统要求

- macOS 15.0 Sequoia 及以上
- ad-hoc 签名、未公证：首次打开请右键 →「打开」
- 仅 TUN 需要一次管理员授权，系统代理不需要密码
