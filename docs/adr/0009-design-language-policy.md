# ADR-0009 · 设计语言：自绘控制中心风格，26+ 只适配系统部件

- 状态：已接受
- 日期：2026-11-13
- 相关：`docs/02-UI-SPEC.md`、`.agents/skills/menubar-ui/SKILL.md`

## 背景

macOS 26 引入 Liquid Glass，应用用新 SDK 重编后，**系统渲染的部件**会自动换新外观。我们的面板是自绘的（`NSVisualEffectView` 材质 + 自绘卡片/胶囊/分段），不会自动变玻璃。

用户选择：**保持一致**，不追两套外观。

## 决定

1. **面板视觉在所有系统上保持一致**（控制中心风格），不为 26+ 单独出一套皮肤
2. 系统部件（右键菜单、弹窗、`NSOpenPanel`、输入框、滚动条、浮层窗口圆角与阴影）**跟随系统**，不做干预
3. **不使用** `UIDesignRequiresCompatibility` 之类的回退键：Apple 明确表示下个大版本移除，属拖延
4. 若将来要上玻璃（26+）：只换「面板底」这一处，卡片仍是半透明 fill，**严禁玻璃叠玻璃**；且必须先验证三件事——浅色壁纸下的正文对比度、Reduce Transparency 下的回退、以及菜单栏浮层与桌面之间的边缘是否糊
5. 技术入口已在 `PanelMaterialView` 注释里写明；**现在不写分支、不留空抽象**（等真的要做得起来再改）

## 理由

- 自绘面板是我们的识别度来源，跟着系统改版等于每两年重做一次视觉
- 玻璃叠在半透明卡片上可读性风险高，验收成本翻倍，收益只是「更像系统」
- v1 的核心是能正常代理，不是外观追新

## 后果

- 26/27 上会看到「面板是控制中心风、周围菜单是玻璃风」的轻微混搭，接受
- 系统语义色与 SF Symbols 可能随系统微调，属于正常，不做 pixel 对齐
- 若未来真上玻璃，改动范围限定在材质层 + token，视图层不动
