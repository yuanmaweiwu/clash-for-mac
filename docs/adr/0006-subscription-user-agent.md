# ADR-0006 · 订阅请求的 User-Agent 策略

- 状态：已接受
- 日期：2026-11-13
- 相关：`docs/01-ARCHITECTURE.md` §4.1

## 背景

用真实订阅实测（2026-11-13，某机场）发现：机场按 **User-Agent** 决定返回内容。

| UA | 响应 |
|---|---|
| `Clash/0.1 (prototype)` | `422 {"detail":"此客户端格式不支持当前套餐节点，请选择其他格式"}` |
| `mihomo/1.19.34` | `200` + Clash YAML |
| `clash-verge/v2.0.0` | `200` + Clash YAML |
| `ClashMetaForAndroid/2.11.6` | `200` + Clash YAML |

响应头另有 `Vary: Authorization`，说明同一 URL 在不同身份下可能返回不同内容。

## 决定

1. 订阅请求默认发送 **`mihomo/<bundled core version>`**（如 `mihomo/1.19.34`）：与自带内核一致，最不容易被识别成陌生客户端
2. UA 可在设置里改为预设之一：`mihomo/<ver>`（默认）、`clash-verge/v2.7.0`、`ClashMetaForAndroid/2.11.6`、自定义字符串
3. 收到 `422` / `403` / 非 YAML 内容时：**自动用下一个预设 UA 重试一次**，仍失败则报「该订阅不支持本客户端，可在设置里更换 UA」，并把状态码与内容类型（不含 URL 参数）写进日志
4. UA 只用于订阅拉取，不影响其他网络请求

## 理由

- 不伪装成浏览器：部分机场对浏览器 UA 返回 HTML 订阅页而非配置
- 默认与内核版本一致，避免「内核 v1.19 却报 v2.x」这类无谓差异
- 自动降级重试把绝大多数机场兼容掉，用户不必理解 UA 是什么

## 后果

- `ProfileStore` 需要 UA 列表 + 一次性重试逻辑；`lastError` 要能区分「格式不支持（422）」与「网络错误」
- 设置面板需要一项「订阅 UA」（高级项，默认折叠）
- 后续若遇到按 UA 返回**不同节点集**的机场，用户切 UA 会导致节点变化——必须在切换时提示「需要重新拉取订阅」
